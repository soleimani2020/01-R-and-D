House Price Prediction with Linear and Regularized Regression

Project 11 · Supervised learning · Regression · Model selection

Question: Can property characteristics be used to estimate a home's sale price, and how do ordinary linear regression, Ridge regression, and Elastic Net compare on test data that was held out from model development?

Workflow: load and inspect the data → create the train/test split → build one leakage-free preprocessing + model Pipeline → fit a mean-predictor baseline → tune Ridge and Elastic Net with cross-validation → select the model by cross-validated RMSE → evaluate on the held-out test set once → analyse errors.

Data: the Ames Housing training file (1,460 homes, 79 features plus an Id column and the SalePrice target). The notebook reads a local house_price.csv if one is present and otherwise downloads the same data from GitHub. The identifier is used as the DataFrame index and is not a predictor.

Design note: every preprocessing step (imputation, one-hot encoding, scaling) lives inside the pipeline. During cross-validation the pipeline is re-fitted on each training fold, so validation folds never influence their own preprocessing. The test partition is touched only for the final evaluation.

5. Missing values (training data only)

The summary below is computed on the training partition. In this dataset most missing values are not random: for columns such as PoolQC, FireplaceQu, Garage* and Bsmt*, NaN means the house does not have that feature. That is why categorical gaps are filled with an explicit "None" category inside the pipeline instead of the most frequent value (mode), which would invent a pool, fireplace or garage that does not exist.

Note on data leakage. What matters for leakage is where a decision is learned from, not which DataFrame it is applied to. The columns to drop are chosen using the training set only (X_train.isna().mean() > 0.80), so the test data has no influence on the choice. The resulting list, columns_to_drop, is then applied identically to X_test so that both sets have the same features. Otherwise, the fitted pipeline would receive columns it was not trained on and raise an error.

6. Build the preprocessing pipeline

A ColumnTransformer splits the columns into groups and runs a different preprocessing chain on each group. This matters here because numeric and text columns need different treatment. The results are then joined side by side into one feature matrix for the model.

Column type Steps
Numeric median imputation (plus a missing-indicator flag) → standardization
Categorical fill missing with "None" → one-hot encoding (unseen categories ignored)

Scaling numeric features. Numeric columns are standardized with StandardScaler (mean 0, standard deviation 1). Features sit on very different scales (e.g. LotArea in the thousands vs. OverallQual from 1 to 10). Ridge and Elastic Net penalize coefficient size, so unscaled features would be penalized unevenly. Scaling makes the penalty fair and the coefficients comparable (dollars per +1 standard deviation). The scaler's mean and standard deviation are learned from training data only, and are re-fitted inside each CV fold.

Encoding missing categoricals. Missing values in categorical columns are first filled with the string "None". For many columns (e.g. GarageType, FireplaceQu, BsmtQual) a missing value means the house has no such feature, so "None" is a meaningful category. The one-hot encoder then treats it like any other category and creates its own 0/1 column (e.g. GarageType_None), which tells the model "no garage".

Because this transformer is the first step of every model's Pipeline, it is re-fitted on the training portion of each CV fold. No statistic (median, scaler mean/std, category list) is ever computed from validation or test rows.

In [68]:
# Split columns by type
num_cols = X_train.select_dtypes(include="number").columns.tolist()
cat_cols = X_train.select_dtypes(exclude="number").columns.tolist()
print(f"{len(num_cols)} numeric and {len(cat_cols)} categorical predictors")

# Numeric chain
numeric_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="median", add_indicator=True)),
    ("scale", StandardScaler()),
])

# Categorical chain
categorical_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="constant", fill_value="None")),
    ("onehot", OneHotEncoder(handle_unknown="ignore", sparse_output=False)),
])

# Combine
preprocess = ColumnTransformer([
    ("num", numeric_pipe, num_cols),
    ("cat", categorical_pipe, cat_cols),
])


# Attach a model
def make_pipeline(model):
    return Pipeline([("prep", preprocess), ("model", model)])

7. Cross-validation setup and baseline models

All candidates are compared with the same 5-fold splits and the same metric (RMSE, in dollars). A DummyRegressor that always predicts the training mean is included as a floor: any real model must beat it.

In [69]:
cv = KFold(n_splits=5, shuffle=True, random_state=RANDOM_STATE)

def cv_rmse(estimator):
    scores = cross_val_score(estimator, X_train, y_train, cv=cv, scoring="neg_root_mean_squared_error")
    return -scores   # per-fold RMSE

baseline_folds = cv_rmse(make_pipeline(DummyRegressor(strategy="mean")))
ols_folds = cv_rmse(make_pipeline(LinearRegression()))

print("Mean-predictor baseline  CV RMSE: %.0f  (folds: %s)" % (baseline_folds.mean(), np.round(baseline_folds).astype(int)))
print("Linear Regression        CV RMSE: %.0f  (folds: %s)" % (ols_folds.mean(), np.round(ols_folds).astype(int)))
 
Mean-predictor baseline  CV RMSE: 77067  (folds: [78942 61842 76615 73865 94069])
Linear Regression        CV RMSE: 39208  (folds: [29811 27610 56321 40012 42287])

Analysis of the folds.

  • Baseline: always predicting the average price is off by about $77k RMSE. This is the floor that any real model must beat.
  • Linear Regression: it cuts the error roughly in half (≈ $39k), but it is unstable. Most folds are around $28–42k, while one fold is about $56k.
  • Why it is unstable: the model has about 300 input columns but only about 820 training homes in each fold. Ordinary least squares can set each coefficient as large as it likes, so a few unusual homes can pull the coefficients far off. The model then does badly on homes it has not seen.
  • What comes next: Ridge and Elastic Net add a penalty that keeps the coefficients from growing too large. That should make the model more stable.

8. Tune Ridge and Elastic Net with GridSearchCV

The regularization strength alpha (and, for Elastic Net, the L1/L2 mix l1_ratio) is chosen by cross-validated RMSE on the training data only. Because the grid search wraps the full pipeline, preprocessing is re-fitted inside every fold.

13. Which features matter?

What the code does

  • Pulls the preprocessing step and the linear model out of the best pipeline, and matches each coefficient to its feature name.
  • Prints how many coefficients are non-zero (how many features the model actually uses).
  • Plots the 10 largest numeric coefficients as a bar chart (green = raises price, red = lowers price). Because numeric features are standardized, each bar means dollars per +1 standard deviation.
  • Shows a table of the 8 largest categorical coefficients, with how many training homes fall in each category, so you can spot large effects that rest on only a few homes.

  • Rare categories are unreliable: The biggest coefficients (RoofMatl_ClyTile ≈ −$408k, Condition2_PosN ≈ −$122k) rest on just 1 and 2 homes, so the model is memorising single sales. Well-supported ones (Neighborhood_NoRidge, 28 homes; KitchenQual_Ex, 65 homes) are far more trustworthy.

14. Conclusions and limitations

Answer to the question. Yes. Property characteristics explain roughly 90% of the variation in sale prices on held-out homes (test R² ≈ 0.90, median absolute error ≈ $12k, RMSE ≈ $27k, against ≈ $84k test RMSE for always predicting the mean).

Model comparison. With preprocessing done inside cross-validation and alpha/l1_ratio tuned, Elastic Net performed best: it had the lowest CV RMSE (≈ $34.1k vs. ≈ $39.2k for Linear Regression) and the lowest test RMSE (≈ $26.6k vs. ≈ $28.1k). Plain least squares is unstable with this many correlated and sparse columns, which explains its weaker CV score. Ridge beat Linear Regression in CV (≈ $35.1k), but not on the test set (≈ $29.5k vs. ≈ $28.1k), so its advantage is small and within split-to-split noise. Elastic Net was selected using CV only and then confirmed on the test set.

Limitations.

  • The test set has 438 homes and is one split; small differences between models (especially Ridge vs. Linear Regression) are within split-to-split noise. Repeated CV or several random splits would give tighter estimates.
  • A linear model on raw price under-predicts expensive homes and has non-constant error variance; a log-price target is the obvious next improvement.
  • One-hot coefficients for very rare categories are unreliable.
  • Results come from a single city and period (Ames, Iowa, 2006–2010) and should not be applied to other markets without re-validation.

What we learn from this project

  • Regularization helps. Elastic Net and Ridge beat plain Linear Regression because many columns are correlated.
  • Pick the model with cross-validation, then check once on the test set. That gives an honest final score.
  • Use more than one metric. The typical error (12k) is smaller than RMSE (27k) because a few big misses count extra.
  • Look at residuals. They show that expensive homes are under-predicted.
  • Size, quality and age drive price. Living area, build quality and year built matter most.
  • Rare categories are unreliable. Coefficients based on 1-2 homes are just noise.
  • Next step: model log(SalePrice) to reduce errors on expensive homes.
